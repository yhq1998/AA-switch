# macOS：切到 API 后部分 Cowork 会话不可见

排查日期：2026-10-29。用户报告：多个 AA Switch 版本都有此问题，切回账号模式后缺少的会话仍然能看到。

这说明账号侧记录仍在，但不足以证明 API 侧已复制完整。初始修复测试均在隔离目录执行；后续本机核对只读取会话数量、标识和界面，临时切回账号后已恢复 API 模式，未发布安装包。

后续本机核对与用户澄清：账号侧有 3 条本地 Cowork/Tasks 记录，API 侧有 6 条，账号侧缺失于 API 的记录数为 0，API 界面也显示了这 6 条。用户随后确认，额外未显示的记录属于普通 Chat，当前没有发现 Cowork/Tasks 漏同步。下述缺陷来自隔离测试中的兼容性边界，不能据此认定本机发生了任务丢失。

新版界面使用 Tasks 称呼任务。同步按存储目录和会话 ID 识别记录，不按界面标签检索，因此单纯更名不影响同步。普通 Chat 与本地 Cowork/Tasks 是不同的数据来源，当前同步功能不迁移普通 Chat。

## 已复现的原因

在临时目录中运行真实的 `claude-mode.sh desktop gateway`，复现了以下遗漏；相应测试在修改前失败、修改后通过：

1. **漏扫 `agent/` 子目录。** 原同步只扫描组织目录下的 `local_*.json`。本机 Claude Desktop 4.29.0 的会话管理器同时加载外层和 `agent/` 中的列表项，`sessionType === "agent"` 的任务写入后者。旧版任务可能能同步，放进新目录的任务则完全没有进入同步计划。
2. **漏掉短名正文目录。** 元数据可能叫 `local_<完整 UUID>.json`，正文却保存在 `<UUID 前 8 位>/`。旧脚本只找同名的 `local_<完整 UUID>/`，找不到仍复制元数据并记录同步成功；之后两边活动时间相同，重复切换也不会补正文。
3. **选中旧账号目录。** 账号和组织目录也支持 UUID 前 8 位。完整 UUID 与短名目录共存时，原脚本优先使用完整目录，可能同步的是旧列表。程序代码中存在对应的短名优先选择逻辑。
4. **过滤掉合法 ID。** 原正则不接受 `local_` 后的额外下划线。Claude 的合法会话名包括 `local_ditto_<id>_g<n>`；这些记录原先被静默忽略。
5. **同步账本跨目录混用。** 原账本仅按会话 ID 记录活动时间。API 本地身份或存储目录改变时，旧账本会把新目录里缺少的旧会话当成“已经主动删除”，不再补齐。

这些都是能造成所报现象的确定代码缺陷。反馈用户具体命中了哪几项，仍需在其机器上核对目录结构与缺失会话 ID；当前没有其会话样本，不能把某一项断言为唯一原因。

## 修复行为

- 同步外层和 `agent/`，保留会话所在层级；已知账号身份时优先匹配短名，避免回退到其他账号。
- 支持完整名、短名正文目录，复制到目标的完整会话名下，并改写 `cwd`、transcript 路径以及 `.claude/projects` 目录名；签名的 `audit.jsonl` 保持原样。
- 元数据活动时间相同但一边缺正文时，重新补齐；源正文不存在时报告失败，不再制造只有列表项的“成功副本”。
- 接受额外下划线。
- 按账号/API 目录对分别保存账本，保留切回旧目录时的删除、冲突状态；旧账本路径保留最近一次同步快照。
- 脚本版本更新到 `1.4.6`，供应用安装新脚本（本机旧安装已用过 `1.4.5`，因此继续递增，防止包内旧脚本覆盖修复）。

## 验证

```bash
python3 -m unittest discover -s tests -p test_claude_desktop_mode.py -k cowork -v
/bin/bash smoke-test.sh
```

回归覆盖目录遗漏、短名正文及路径重写、签名日志不变、旧版不完整副本修补、换 API 目录、切回原目录、删除和冲突保留、复制失败后重试，以及旧账本迁移。测试中的应用、进程、钥匙串、网络操作均由替身隔离。

## 受影响用户的恢复与边界

修复需要更新脚本或安装包含它的新版本，旧安装包不会自动获得仓库改动。更新后，彻底退出 Claude，再通过 AA Switch 重新应用 API 配置；切换流程会执行同步。也可以在 Claude 退出后运行更新后的 `claude-mode desktop sync`。

原始账号会话仍在时，本次修复能补齐漏扫目录、合法 ID 和同时间戳的正文缺失。仍需在受影响机器确认 API 中的列表、打开对话和继续对话三个步骤，隔离测试不等于真实桌面端验收。

保留以下边界，避免误恢复用户主动删除的会话：

- 旧账本不记录目录来源，首次升级会沿用其删除判断并绑定当时的目录对。若旧账本已经将“一边完全缺少的列表项”误记为删除，无法自动区分真实删除与漏同步，需要核对对应会话后单独恢复，不能直接清空全部账本。
- API 侧从未初始化过 Cowork 时，仍会提示先初始化后再同步；不会猜测并创建账号身份目录。
- 两边都续聊过的冲突会话继续各自保留，不自动合并。
- 未取得 API 当前身份时，多候选目录仍沿用会话数启发式选择；此次仅修复了同一身份的新旧长短目录优先级。多身份现场需单独核对目标目录。
